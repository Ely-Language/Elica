# Ely — полное описание языка и план работ

---

# Часть I. Спецификация языка Ely

## 1. Общие характеристики

| Свойство | Значение |
|---|---|
| Название | Ely (Elica) |
| Типизация | Гибридная (не постепенная): статика и динамика максимально конверсируемы |
| Парадигма | F3OPL (Field-oriented OOP) + процедурная + C/C++-интероп |
| Потоки | EMSTC по умолчанию; всё `thread_local` или `global`. Смешивание с C++-потоками — непредсказуемо |
| Совместимость | Полная с C/C++ (типы, объявления, вызовы) |
| Расширения | `.ely` — исходники, `.elyc` — модули |
| Точка входа | `manager.json` → `"enter"` |
| Разделители | `;` — конец **expression**, `{}` — тело **statement** |
| Доступ | Только `.` (перегружена): члены, пространства имён, типы C/C++, пути модулей |

---

## 2. Лексика

### 2.1. Комментарии
- `// ...` — строчный
- `/* ... */` — блочный (C-style)

### 2.2. Литералы

| Литерал | Токен |
|---|---|
| Целые | `INT_LITERAL` |
| Плавающие | `FLT_LITERAL` |
| Строки | `STR_LITERAL` |
| Символы | `CHAR_LITERAL` |
| Многострочные | `MULTILINE_STR_LITERAL` |
| Интерполированные | `F_STR_LITERAL` (`f"..."`, `f'...'`) |
| Многострочные интерполированные | `F_MULTILINE_STR_LITERAL` (`f"""..."""`) |

Интерполяция — через `{...}` (как в Python).

### 2.3. Спецсимволы
- `@` — текстовые макросы
- `#` — компиляторные макросы
- `&` — структурные макросы
- `^` — оператор (степень по умолчанию, если не переопределён; иначе C++ XOR)

---

## 3. Типы

### 3.1. Целые
`byte`, `ubyte`, `short`, `ushort`, `int`, `uint`, `more` (64), `umore` (64)

### 3.2. Плавающие
- `flt` — float
- `double` — double
- `noised` — double без экспоненты, диапазон [0, 1] (дробь `1111...` = 1)

### 3.3. Строковые
- `str` — строка (временно маппится на C++ `__YS::ystr` через `@str`)
- `atom` — внутренний интернированный тип (пользователь не использует)
- `char` — символ

### 3.4. Прочие
- `bool`
- `void`
- `sentinel` — `null | undefined` (на уровне фреймворка ≈ `enum void`, точная семантика WIP)
- `any` — динамический, может быть указателем на сырой или GC-объект

### 3.5. Конверсия
- Компилятор сам анализирует и приводит типы на этапе семантического анализа (бэкенд доступен)
- `any` ↔ статика — свободно

---

## 4. Декларации

### 4.1. Общий формат

```
[модификаторы] [тип] [ключевое_слово_декларации | ∅] [имя] [детали] [syntax_item]
```

`syntax_item`:
- **expression** — всегда `;`
- **statement** — всегда `{ ... }`
- **Всё может быть и expr, и stmt**, кроме переменной (только expr)

### 4.2. Функция

```ely
[мод.] <тип> func <имя> ( <параметры> ) { <тело> }
```

- Параметры: `<тип> <имя> [= <значение>]`
- Перегрузка по типам — поддерживается
- `void` — `return` не нужен
- `main` — автовставка `return 0;` перед последней `}`

### 4.3. Переменная

```ely
[мод.] <тип> <имя> [= <expr>] ;
```

### 4.4. Класс / структура

```ely
[мод.] class <Имя> { <члены> }
[мод.] struct <Имя> { <поля> }
```

### 4.5. Модификаторы

| Модификатор | Смысл |
|---|---|
| `public` | Публичный |
| `private` | **C protected** |
| `mine` | **C private** |
| `static` / `stack` / `heap` | Местоположение; для class/struct/typedef — где по умолчанию |
| `copa` / `nocopa` | ≈ `inline`, агрессивно разрешается компилятором |
| `const` | Константность |
| `sealed` | Запрет наследования |
| `abstract` | Абстрактный |
| `wait` / `unwait` | Конструкторные поля (F3OPL, §5) |

---

## 5. F3OPL — Field-oriented OOP

- **`wait`** — поле запрашивает значение при создании объекта класса и всех наследников (можно default)
- **`unwait`** — присваивает значение наследнику и убирает запрос
- **Порядок аргументов конструктора:** без-default → с-default, в порядке объявления полей
- **Порядок полей критичен** → нужны ordered-контейнеры

---

## 6. `this`

- `this` = **this-object scope**, однозначно, **даже при `static`**
- Это не C++-семантика, а scope-ссылка на текущий объект/класс

## 8. Макросы (три типа)

### 8.1. `#` — компиляторные (`CompilerMacro`)

```
#ИМЯ значение;
```

- Хранит `int value`
- Аргумент матчится по имени макроса → `int` (реестр парсеров)
- `#GC 0` ≡ `#GC false`
- `true/1` → `1`, `false/0` → `0`, иначе — `stoi`

### 8.2. `@` — текстовые (`TextMacro`)

Все `@` — **текстовая подстановка**.

| Форма | Пример | Поля |
|---|---|---|
| Object-like | `@PI 3.14;` | `isFunctionLike=false` |
| Type-map | `@str __YS.ystr;` | `isFunctionLike=false`, глобальная замена |
| Function-like | `@out(text) { ... }` | `isFunctionLike=true`, `args` |
| Operator | `@operator<^>(a,b) to(a,b);` | `isOperator=true`, `opString="^"` |

**Гигиена** — только для function-like:
- Без вайтлиста типов; по форме объявления:
  - `<type> func <name>` → `name`
  - `class|struct <name>` → `name`
  - `<type> <name> (= | ;)` → `name`
- Параметры макроса и `main` не переименовываются
- Локальные → `__[буквенная запись номера вставки макросов]_name`

**Расширение:**
- Итеративно, до 100 итераций
- Object-like: замена по границам идентификатора
- Function-like: парсинг `(...)` с балансировкой `(){}[]`, строк, escape
- Operator: инфиксный проход **до** обычного расширения

### 8.3. `&` — структурные (`StructMacro`)

```
&ИМЯ(placeholders...) = targetType {
    preQuotes   = { ... }
    beginQuotes = { ... }
    endQuotes   = { ... }
    postQuotes  = { ... }
    // WIP: fields, waited, unwaited, methods, args
}
```

- `targetType` — только тип/родитель (без `operator` — операторы через `@operator<OP>`)
- Статус: `*Quotes` парсятся; остальное — WIP

---

## 9. Интероп с C/C++

### 9.1. Вставка кода

```ely
cppCode { ... }
cCode   { ... }
```

- **Полностью вне препроцессора**: не сканируются на макросы, не расширяются
- Захват — балансировка `{}` (с учётом строк/комментариев внутри)
- Внутри — произвольный C/C++

### 9.2. Доступ из Ely

- `.` заменяет `::` и `->`
- `__console.ely_out(...)` → `__console::ely_out(...)`
- `__YS.ystr` → `__YS::ystr`

### 9.3. Маппинг типов

- Через `@`-макрос: `@str __YS.ystr;`
- В будущем — нативные 2-байтные строки

---

## 10. Пайплайн препроцессора (обновлённый)

Разделение на **две фазы**:

```
Phase 1: collect (per-file)
    scanProtectedRegions(src) → regions
    collectMacros(src) → project->{compiler,text,struct}Macros
    (по всем файлам проекта)

Phase 2: preprocess (per-file)
    expandTextMacros(src) — только на не-защищённых регионах
    lexer.tokenize()
```

Это гарантирует, что **все макросы всех файлов известны до первого расширения** — кросс-файловые макросы работают.
